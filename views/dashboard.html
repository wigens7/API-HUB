INTEGRATION GUIDE

API documentation

Use your business API key to authenticate requests.

Base URLhttps://your-domain.com/v1

Authentication

Send your API key in the X-API-Key header. Never expose your API key in browser or mobile code.

X-API-Key: zy_test_your_secret_key

Available endpoints

GET/v1/statusCheck API key and workspace status
POST/v1/customersCreate a customer (returns your internal customer id)
POST/v1/customers/:id/kycSubmit identity verification for a customer
GET/v1/customers/:id/kycGet the synced verification status
POST/v1/cardsCreate a card for a verified customer (Idempotency-Key required)
GET/v1/cardsList your cards
GET/v1/cards/:idGet masked card details
GET/v1/cards/:id/historyCard transaction history
POST/v1/cards/:id/fundFund a card from your wallet (Idempotency-Key required)
POST/v1/cards/:id/withdrawWithdraw from a card to your wallet (Idempotency-Key required)
POST/v1/cards/:id/freezeFreeze a card
POST/v1/cards/:id/activateActivate a card
GET/v1/wallet/balanceWallet balance
POST/v1/wallet/deposit-addressGet your USDT deposit address
GET/v1/wallet/depositsConfirmed deposits
GET/v1/wallet/ledgerWallet ledger

Verification fields

Required: id_number, phone_number, date_of_birth, dial_code, id_front_image (Base64), line1, state, postal_code, city, country (three-letter code such as HTI), id_type, occupation, employment_status, account_purpose, annual_salary, expected_monthly_volume and place_of_birth.

Idempotency

Card creation, funding and withdrawal require an Idempotency-Key header (8 to 128 characters). Repeating a request with the same key returns the original result. A response with outcome_unknown means the result is still being verified: do not retry with a new key.

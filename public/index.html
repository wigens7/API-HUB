BUILD YOUR INTEGRATION

GETTING STARTEDQuick startAuthenticationSubmit KYCCreate a cardWebhooks
01 / QUICK START

Connect your business

Each client application should receive a Zytrelix API key. Your backend validates that key, checks the tenant permissions and then calls the provider adapter.

  1. Create a business workspace.
  2. Issue a sandbox API key for that business.
  3. Call your Zytrelix backend, never ZiiroPay directly from browser code.
  4. Complete provider onboarding before enabling production traffic.
02 / AUTHENTICATION

Keep provider credentials server-side

The legacy ZiiroPay card endpoints documented here accept a public_key query parameter. Keep it on the server. Newer ZiiroPay pages also describe Bearer secret-key authentication, so confirm which credential format your account is provisioned for.

POST /api/ziiro/kyc
Content-Type: application/json
x-hub-admin-token: YOUR_INTERNAL_TOKEN
03 / KYC SUBMISSION

Submit customer KYC

Provider documentation requires identity, address, employment and account-purpose fields. Haiti country code is HTI. The ID front image is Base64.

POST /api/ziiro/kyc
{
  "first_name": "Jean",
  "last_name": "Pierre",
  "id_number": "PASSPORT_NUMBER",
  "email": "customer@example.com",
  "phone_number": "50900000000",
  "date_of_birth": "1995-05-10",
  "dial_code": "+509",
  "id_front_image": "BASE64_IMAGE",
  "line1": "Street address",
  "state": "Ouest",
  "postal_code": "HT6110",
  "city": "Port-au-Prince",
  "country": "HTI",
  "id_type": "passport",
  "occupation": "self_employed",
  "employment_status": "employed",
  "account_purpose": "online_purchases",
  "annual_salary": "12000",
  "expected_monthly_volume": "500",
  "place_of_birth": "Haiti"
}

The provider's published endpoint is POST /api/bitvcard/cardkyc. Its documentation lists fields as query parameters. The server adapter currently sends them in the query string. Verify this request format with your ZiiroPay integration contact before production.

04 / CARD ISSUING

Create a virtual card

Only submit a card request after KYC returns approved and you have the provider customer_id.

POST /api/ziiro/cards
{
  "name": "Jean Pierre",
  "customer_id": "PROVIDER_CUSTOMER_ID",
  "amount": "3"
}

Card detail, card transaction history, funding and freeze/activate routes are included in the server adapter.

05 / WEBHOOKS

Receive provider events

Use a dedicated HTTPS webhook receiver. Verify signatures against the exact ZiiroPay webhook signing instructions before processing events. Do not trust an unsigned event or mark a card active based only on a browser response.

The public webhook examples show card-created and card-transaction events. The signature header and signing algorithm must be confirmed with ZiiroPay.
